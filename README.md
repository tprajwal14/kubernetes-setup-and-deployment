# Kubernetes Master and Worker Node Setup

## Project Overview

This project automates the setup of a Kubernetes cluster on Ubuntu Linux using Bash scripts and `kubeadm`.

It covers the installation and configuration of the Kubernetes control-plane (master) node and worker nodes using containerd as the container runtime and Calico as the network plugin.

## Technologies Used

- Ubuntu Linux
- Kubernetes
- kubeadm
- kubelet
- kubectl
- containerd
- Calico
- Bash Scripting
- Git and GitHub

### Script Details

**common.sh**
- Disables swap for the current session.
- Configures required kernel modules and network parameters.
- Installs and configures containerd.
- Installs kubeadm, kubelet, and kubectl.

Run this script on both the master and worker nodes.

**master.sh**
- Initializes the Kubernetes control-plane using kubeadm.
- Configures kubectl access for the current user.
- Installs the Calico network plugin.
- Generates the command required to join worker nodes.

Run this script only on the master node.

## Prerequisites

- Ubuntu Linux machines or virtual machines.
- One master node and at least one worker node.
- Sudo privileges on all nodes.
- Internet access for downloading packages.
- Network connectivity between the master and worker nodes.
- Required Kubernetes and Calico network traffic allowed by firewall rules or cloud security groups.

## Setup Instructions

### Step 1: Clone the Repository

Run on both the master and worker nodes:

```bash
git clone https://github.com/tprajwal14/kubernetes-setup-and-deployment.git
cd kubernetes-setup-and-deployment
```

### Step 2: Configure Both Nodes

Run the common setup script on the master node and every worker node:

```bash
bash common.sh
```

Verify that containerd is running:

```bash
sudo systemctl status containerd
```

### Step 3: Initialize the Master Node

On the master node only, execute:

```bash
bash master.sh
```

The script initializes the Kubernetes control-plane, configures kubectl, installs Calico, and prints a worker-node join command.

Copy and save the complete `kubeadm join` command displayed in the terminal.

### Step 4: Join the Worker Node

On each worker node, execute the join command generated by the master node, using the required sudo privileges.

The command includes the master endpoint and authentication information, so use the exact command generated for your cluster.

### Step 5: Verify the Cluster

On the master node, check the registered nodes:

```bash
kubectl get nodes -o wide
```

Check the cluster pods:

```bash
kubectl get pods -A
```

Wait for the nodes and system pods to become ready. Troubleshoot any networking or configuration issues if they remain in a NotReady state.
